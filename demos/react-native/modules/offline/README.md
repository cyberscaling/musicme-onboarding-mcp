# @demos/offline

Local Expo module wrapping iOS `OfflineCore` (Swift Package) and Android
`offline-core-android` (Gradle library). Demonstrates encrypted offline audio
playback in the RN demo using native players (AVPlayer + ExoPlayer) — no
WebView interception.

## Quick start

```typescript
import { downloadTrack, OfflineModule, OfflineNativePlayer } from '@demos/offline'

const deviceId = await OfflineModule.getDeviceId()

await downloadTrack({
  baseUrl: 'https://secure-stream.musicme.com',
  jwt: '<bearer>',
  trackId: '5400863209100:1:1',
  deviceId,
  metaJson: JSON.stringify({ title: 'Track', artist: 'Artist' }),
})

const tracks = await OfflineModule.listTracks()
await OfflineModule.removeTrack('5400863209100:1:1')
await OfflineModule.wipeAll()

// In JSX:
<OfflineNativePlayer
  trackId="5400863209100:1:1"
  autoPlay
  playing={true}
  seekToMs={null}
  onReady={() => console.log('ready')}
  onTimeUpdate={(e) => console.log('pos ms', e.nativeEvent.position)}
  onEnded={() => console.log('ended')}
/>
```

## Architecture

- **iOS**: `OfflineNativePlayer` hosts `AVPlayer` whose `AVURLAsset` URL uses
  the custom scheme `offline-asset://`. An `AVAssetResourceLoaderDelegate`
  intercepts ranged loading requests and streams AES-CTR-decrypted bytes
  from `BlobStore`.
- **Android**: `OfflineNativePlayer` hosts an `ExoPlayer` configured with
  `DefaultMediaSourceFactory.setDataSourceFactory(OfflineAssetDataSource.Factory)`.
  The custom `DataSource` reads ciphertext from `BlobStore` and decrypts.

Native players give OS lock-screen / MediaSession integration for free, and
keep the audio pipeline outside the WebView attack surface.

Both libraries also expose `OfflineSchemeHandler` (iOS) and `OfflinePathHandler`
(Android) for partners who prefer to keep their existing WebView/MSE
player. The demo does not use them.

## Transport control

Transport is **prop-driven** (not ref methods): set the `playing` prop true/false
to play/pause; set `seekToMs` to a number to seek. JS should reset `seekToMs`
back to `null` after dispatch (a `useEffect` clears it after 100ms).

```tsx
const [playing, setPlaying] = useState(false)
const [seekToMs, setSeekToMs] = useState<number | null>(null)

useEffect(() => {
  if (seekToMs != null) {
    const id = setTimeout(() => setSeekToMs(null), 100)
    return () => clearTimeout(id)
  }
}, [seekToMs])

<OfflineNativePlayer trackId={tid} playing={playing} seekToMs={seekToMs} />
```

## License refresh

`refreshExpiringLicenses` runs on app foreground when online. Tracks whose
`license_exp` is within 7 days are refreshed via POST `/offline/license-refresh`,
then native `OfflineModule.updateLicense` persists the new `license_exp` in
SQLite via the upstream `OfflineCatalog.updateLicenseExp(trackId, exp, iat)`
method (added by Plan 4 T7).

## Storage layout

```
<app sandbox>/offline/
  catalog.sqlite
  blobs/<sanitized-trackId>.bin
```

Plus a single AES-256 master key in iOS Keychain / Android Keystore.

## Build caveats

### iOS — vendored sources

The module vendors `OfflineCore` Swift sources into `ios/OfflineCore/`. Whenever
the upstream `modules/offline-core/` Swift Package changes, re-copy the sources:

```bash
rm -rf demos/react-native/modules/offline/ios/OfflineCore
cp -R modules/offline-core/Sources/OfflineCore \
      demos/react-native/modules/offline/ios/OfflineCore
cd demos/react-native/ios && pod install
```

### Android — settings.gradle re-application

`demos/react-native/android/settings.gradle` is regenerated by every
`bun run prebuild`. The `:offline-core-android` include must be re-applied
after every prebuild:

```groovy
include ':offline-core-android'
project(':offline-core-android').projectDir = new File(rootProject.projectDir, '../../../modules/offline-core-android')
```

A small post-prebuild script `scripts/post-prebuild-android.sh` could automate
this — see open issue / TODO. Until then, manual re-application is required.

## Maestro flows

```bash
# Install Maestro (one-time, requires bash + curl):
curl -Ls "https://get.maestro.mobile.dev" | bash

# Run flows:
cd demos/react-native
maestro test maestro/download-and-play-offline.yaml
maestro test maestro/refresh-license.yaml
maestro test maestro/logout-wipes-offline.yaml
```

Each exits 0 on success. Selectors in the flows reference test IDs
(`download-button-0` etc.) that may need to match what `DownloadButton`
actually emits — adjust if Maestro reports `Element not found`.

## Known limitations

- Transport controls require Plan 4 T8's prop-driven wiring (not `ref.play()`).
- `mid` field on `OfflineTrack` is hardcoded to `0` because upstream
  `OfflineTrackRow` doesn't persist it. The JS facade keeps the field for
  type-stability; consumers should not rely on it. Fix would require an
  upstream schema change in `modules/offline-core{,-android}`.
- Background download lifecycle (URLSession `.background` / WorkManager) is
  not wired — downloads happen during app foreground only.
- `AndroidKeyStoreKeyVault` is not unit-tested at the JVM level (Robolectric
  doesn't ship the AndroidKeyStore shadow). Plan 4 Maestro flows on
  emulator exercise it indirectly via end-to-end download + playback.
